# Database

## Technology and Connection

- Database: MongoDB.
- ODM: Mongoose 9 through `@nestjs/mongoose`.
- Schema source: `apps/api/src/schemas/index.ts`.
- Connection source: `apps/api/src/database.ts`.
- Required environment variable: `MONGODB_URI`.
- Local default/example: `mongodb://localhost:27017/studyapp`.
- Expected production deployment: MongoDB Atlas with its connection string supplied only through environment configuration.
- Schema option `timestamps: true` adds `createdAt` and `updatedAt` to every top-level collection.
- JSON serialization changes `_id` to string `id` and removes `_id`/`__v` on top-level documents. Embedded distractions do not use that transform and retain their embedded `_id`.

There are no PostgreSQL tables, Prisma schema, or migration commands.

## Collections

### `users`

Purpose: account identity and refresh-token revocation.

- `email: string` — required, lowercase, trimmed, max 254.
- `passwordHash: string` — required, excluded from normal queries.
- `name: string` — required, trimmed, 2–80 characters.
- `timezone: string` — default `UTC`; settings service validates IANA names before update.
- `refreshTokenHash: string | null` — default null, excluded from normal queries.
- timestamps.

Index: unique `{ email: 1 }`.

The refresh token itself is never stored; bcrypt compares it with `refreshTokenHash`.

### `subjects`

Purpose: user-owned study categories.

- `userId: ObjectId -> User` — required.
- `name: string` — required, trimmed, max 80.
- `description?: string` — max 500.
- `color: string` — default `#8B9DFF`, six-digit hex.
- `icon: string` — default `book`, max 40.
- `weeklyTargetMinutes: number` — default 0, range 0–10080.
- `isActive: boolean` — default true.
- timestamps.

Indexes: `{ userId: 1 }`; unique `{ userId: 1, name: 1 }` (case-sensitive; no collation is configured).

Deletion is rejected when tasks, timetable entries, or focus sessions reference the subject.

### `tasks`

Purpose: concrete work items.

- `userId: ObjectId -> User` — required.
- `subjectId?: ObjectId -> Subject`.
- `title: string` — required, trimmed, max 160.
- `description?: string` — max 2000.
- `priority: LOW | MEDIUM | HIGH` — default `MEDIUM`.
- `estimatedMinutes?: number` — 1–10080.
- `dueAt?: Date`.
- `completedAt?: Date`.
- `status: TODO | IN_PROGRESS | COMPLETED` — default `TODO`.
- timestamps.

Indexes: `{ userId: 1, status: 1 }`; `{ subjectId: 1 }`.

### `timetableEntries`

Purpose: recurring weekly plans. These are not sessions.

- `userId: ObjectId -> User` — required.
- `subjectId: ObjectId -> Subject` — required.
- `taskId?: ObjectId -> Task`.
- `title: string` — required, trimmed, max 160.
- `dayOfWeek: number` — required, 0–6 (`0=Sunday`).
- `startTime: string` — required `HH:mm`.
- `endTime: string` — required `HH:mm`; service enforces end after start.
- `targetMinutes: number` — required, 1–1440.
- `isEnabled: boolean` — default true.
- timestamps.

Index: `{ userId: 1, dayOfWeek: 1 }`.

The service verifies that an optional task belongs to the selected subject.

### `focusSessions`

Purpose: authoritative focus lifecycle and analytics input.

- `userId: ObjectId -> User` — required.
- `subjectId?: ObjectId -> Subject`.
- `taskId?: ObjectId -> Task`.
- `clientSessionId?: string` — max 120; idempotency key for offline-created sessions.
- `startedAt: Date` — required.
- `endedAt?: Date`.
- `pausedAt?: Date`.
- `totalPausedSeconds: number` — default 0, non-negative.
- `plannedMinutes: number` — required, 1–1440.
- `actualMinutes: number` — default 0; server-derived.
- `reminderIntervalMinutes: number` — required, 1–240.
- `status: ACTIVE | PAUSED | COMPLETED | CANCELLED | EXPIRED` — default `ACTIVE`.
- `completionPercentage: number` — default 0, 0–100.
- `distractionCount: number` — default 0.
- `distractions: EmbeddedDistraction[]` — default `[]`.
- timestamps.

Embedded distraction:

- `_id` generated by MongoDB/Mongoose.
- `type: PHONE | SOCIAL_MEDIA | MESSAGING | FATIGUE | OTHER` — required.
- `note?: string` — max 500.
- `occurredAt: Date` — default current time.

Why embedded: the event has no independent ownership/lifecycle, is always associated with one bounded session, and is normally read/aggregated with that session. `distractionCount` is denormalized for cheap analytics.

Indexes:

- `{ userId: 1 }`
- `{ startedAt: 1 }`
- `{ userId: 1, startedAt: -1 }`
- `{ userId: 1, endedAt: -1 }`
- `{ userId: 1, status: 1 }`
- unique partial `{ userId: 1, clientSessionId: 1 }` when `clientSessionId` is a string
- unique partial `{ userId: 1 }` when status is `ACTIVE` or `PAUSED`, named `one_open_focus_session_per_user`

### `userSettings`

Purpose: one current preference/goal record per user.

- `userId: ObjectId -> User` — required.
- `defaultFocusMinutes: number` — default 50, 1–1440.
- `defaultReminderIntervalMinutes: number` — schema range 1–240; update DTO currently permits 5/10/15/20/25/30; default 10.
- `dailyStudyTargetMinutes: number` — default 180, 1–1440.
- `weeklyStudyTargetMinutes: number` — default 1260, 1–10080.
- `minimumStreakMinutes: number` — default 30, 1–1440.
- `theme: DARK | LIGHT | SYSTEM` — default `DARK`.
- `soundEnabled: boolean` — default true.
- `vibrationEnabled: boolean` — default true.
- `notificationsEnabled: boolean` — default true.
- timestamps.

Index: unique `{ userId: 1 }`.

### `studyGoals`

Purpose: schema reserved for period-specific goals.

- `userId: ObjectId -> User` — required.
- `period: DAILY | WEEKLY | MONTHLY` — required.
- `targetMinutes: number` — required, 1–10080.
- timestamps.

Index: `{ userId: 1 }`.

Current discrepancy: the seed script creates daily/weekly documents, and data reset deletes them, but there is no goals module/controller/service and analytics/dashboard use target fields from `userSettings`. Treat this collection as dormant, not an implemented goals API.

## Ownership

INVARIANT: protected services derive `userId` from the validated JWT. Every read/update/delete query includes that owner. Relation validation also checks the referenced subject/task belongs to the same user.

## Seed Data

`npm run seed:dev --workspace=api` executes `apps/api/scripts/seed.ts`.

It creates, if absent:

- `demo@studyfocus.app` / `password123`
- default settings
- Mathematics subject
- daily and weekly `studyGoals`

The script is idempotent only at the demo-user level: if the user exists, it does not recreate related seed records. It prints existing focus-session count. Never use the demo password in production.

## Operations

Start local MongoDB, create `apps/api/.env`, then:

```powershell
npm run dev:api
Invoke-RestMethod http://localhost:3000/api/v1/health/database
npm run seed:dev --workspace=api
```

Mongoose creates collections/indexes as models initialize. There is no migration runner and no application-level MongoDB transactions. Schema/index changes must be reviewed for production rollout and existing-data compatibility. Destructive operations such as settings reset run as independent parallel deletes.
